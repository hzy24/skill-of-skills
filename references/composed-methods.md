# 方法适配与计划履约

SoS 负责选能力、组织计划、跟踪执行。专业分析、判断和专业检查由选定 Skill 完成。

## 规划时核对适配

首次规划通过 flow.py assess 记录候选判断，用 route-template 的结构填写并 route 登记业务阶段。程序分别生成只读 context_file 与简短 review_file。宿主核对阶段目标、方法用途及关键前提，只填 need、verdict、reason，通过 review 登记判断后 publish。引用与来源版本由程序维护。来源核验、结构校验与宿主适配判断分别记录。专业字段解释与规则应用在执行阶段完成。采用统计、数据分析等可迁移方法时，审阅同时核对已登记的负责范围、比较理由和未覆盖判断的处理安排；来源绑定只证明读过实际方法，不能自动证明该方法足以回答业务问题。

用户修改或换用技能后，method_review.py 复核受影响的专业委托。未变化阶段的真实判断按来源和阶段摘要复用，纯标题调整保留审阅。引用由程序提供，宿主核对任务契合度与实质限制；不要求逐字段同义证明，不提前完成专业分析。确认新版方案后继续执行。

## 执行后核对计划

capture 生成同一份核对表：

- items：按 plan 已确认的标准逐项核对输出、文件位置及约定检查记录。
- quality.observed_skills：实际采用的准确技能名，与 plan 绑定和执行日志对照。
- quality.findings：尚未解决的计划偏差；没有偏差填空列表。
- quality.result：本模块是否按计划完成。

无需额外填写 claims 或重新分析专业结论。专业 Skill 负责专业检查；SoS 核对该检查是否按计划完成及其交付记录。真实工具调用 JSON 可在 submit 时通过 --trace 传入，辅助核对实际调用。全部约定成果和检查通过后 accept；最终 audit 核对全计划完成情况。

新增技能通过 rebind.py 更新分工，再继续执行。修改成果后重新 capture，保留文件版本和记录关联。
