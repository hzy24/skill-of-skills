# 最终产物的证据检查

确认执行后，用于分析报告、比较决策及跨文件交付。规划阶段只确定检查标准，按 planning.md 形成方案。简单任务保留一项对照原文的审阅即可。

## 先确定方法与事实

当前选型协议统一使用 capability_needs：standard 写合格条件，existing_assessment 写覆盖依据，decision.application 写方法对应的内容项和保留、调整或补充的安排；gap/discovery/fallback_limit 记录缺口及实际范围。旧计划的 method_assessment 仅用于兼容。

将关键事实保存在任务目录的 facts.json，至少记录对象、期间、单位、基数/分母、来源定位、数值或主张、已知/计算/假设/待核实状态。计划、底稿、图表、摘要和最终聊天从同一份事实读取。原始数据不完整时补读；缺少材料保留为未知，不能推成不存在。历史差额、业务原因和未来判断分别给出证据。简单任务可直接引用原文，省略事实文件。

## 数字检查

每个合计或桥图分别核对起点、完整组成、终点。将本期值与跨期变化分别组织；情景标题中的客户、项目、产品范围须与计算基数一致。对照最终显示的百分比/百分点/单位，不能只看公式缓存。判断比例的分母和判断原因所需证据也要核对。

`verify_numbers.py` 使用标准库从最终文件读取指定数字，不执行文件内代码。xlsx读取缓存值，须先使用表格引擎重算；PPT按页定位段落。所有定位表达式必须唯一命中，目标数字使用命名组 `(?P<value>...)`。可跨文件比较，具体模式见 references/numeric-checks.json。运行：

```
python <skill>/scripts/verify_numbers.py numeric-checks.json --out numeric-results.json
```

退出码0只证明所列数字关系成立；1表示至少一项未通过；2表示输入错误。金额、期间、对象等 context 是宿主阅读标签后登记的口径，程序只检查一致性，不会独立理解客户归属。验收必须同时包含相关语义审阅，禁止把局部数值通过扩大为整份成果通过。

## 视觉与刷新检查

重新读取最后生成的文件并渲染关键页。核对遮挡、可读性与图表表达是否符合数据含义。数值桥图等特殊图形按其具体语义检查。

图片工具如描述文件不存在的年份、对象或数据，停止沿其描述修图。与原文件文本、形状位置、真实渲染交叉核对。工具不能可靠读图时将视觉项记为 unverified，说明范围；可以交付待复核草稿，不能标为视觉通过。不要为了缩成一页而牺牲可读字号。

承诺“改数即可复算”前，在副本改变一个代表输入，重算并检查所有依赖的摘要、表格和图表，随后丢弃副本。没有刷新验证时只说明实际公式覆盖范围。

## 每项审阅与版本绑定

`execute.py capture` 从实际文件生成审阅表，保存本次文件版本与检查标准。新方案同时生成 quality：[实质审阅](composed-methods.md)按随包 grader 检查实际主张、执行记录和标准遗漏。数字或格式正确无法证明原因解释成立；缺少过程证据的原因写为待核实假设，建议明确依据和适用条件。

逐项读取成果，在生成的 `review.json` 中填写 result（pass/fail/unverified）、locator（具体位置）、method（实际检查方法）、observed（观察到的结果）。检查 ID、标准和快照由程序负责；不用填写哈希或另造审阅格式。

`accept` 核对所有检查项、快照和当前文件。任一项未通过或文件改变都会阻止完成。修改待审成果后重新 `capture`，新表全部回到 unverified，重新读取并审阅；历史快照保留在执行记录中。方法原文或来源数据改变时重新核验输入与能力，不能只刷新成果。人工确认节点保存用户真实决定。未解决项保留为 fail/unverified，说明可交付草稿的范围。

修改文件后重新核对受影响的数字、引用、文字及布局，最后再生成交付记录。总结只说实际验证过的范围。内容尚未解决时可交付带问题说明的草稿，并保留 failed 状态。

## 控制反复修补与上下文漂移

同一问题两轮修改仍未收敛，先定位当前文件的具体证据，选择简化布局、重建局部或明确未验证范围。不要重复全量阅读技能与输出全文；保存失败项、路径、版本、下一步到短检查点。上下文压缩后重新读取当前 plan.json、facts.json 和实际产物；摘要中的数字和“已通过”只作导航。内容调整不改变业务范围时复验即可，涉及用户取舍时再更新方案并对齐授权。

节点 start 记录输入文件 SHA256；finish、review、下游 start 和 audit 检查来源版本。来源变化时重新核验受影响节点；同一路径的新文件不能沿用旧审阅。
