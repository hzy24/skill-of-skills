# 规划深度：让用户决定范围，让技能展开工作

首次规划遵循 planning.md。专业性体现在选对方法、抓住本次问题、明确关键约束和验收。列满步骤并不能增加专业性。

## 两层责任

方案明确：为谁解决什么问题、采用什么能力及依据、材料和缺口、交付范围、必要交接、怎样判断完成。一个成熟 Skill 能整体完成时，安排一个模块。

专业 Skill 在执行阶段安排：内部研究与诊断、算法选择细节、草案正文、逐页设计、工具调用顺序、异常分支和修复。方法揭示的新线索在原范围内继续调查。改变用户目标、交付范围或权限时再对齐。

## 按用户需要做的决定确定粒度

| 任务 | 首份方案里的具体内容 | 交给专业技能展开 |
|---|---|---|
| 经营分析 | 本期对象和口径；材料显露的重点变化、现金或集中度疑问；报告用途及证据要求 | 全量核算、归因、重点项目筛选与报告正文 |
| 招聘材料 | 岗位、对象、用户提供的条件和模板；一致性要求及缺失条件 | 逐人核对、草拟文本、制作文档；出现未授权条款时再对齐 |
| 文献评估 | 研究问题、纳入范围、比较维度与引用要求 | 检索策略细化、筛选、证据评价与综合 |
| 排程优化 | 资源、约束、优化目标、可行性与效果验证 | 建模、算法、求解、不可行诊断与结果解释 |
| 软件修复 | 受影响行为、兼容边界、复现材料与回归要求 | 定位根因、选择实现、修复及测试循环 |
| 演示汇报 | 受众、目的、时长、主题顺序与关键证据 | 具体页数、逐页论点、图表与版式 |

上表为思路示意。具体问题从本次材料和实际 Skill 推导；不要照抄业务清单。用户已有明确细纲、页数或算法要求时保留。只有详细设计会影响用户的实质决定，或用户明确要求先看细纲时，才在规划中展开它。

`content_outline` 保存可修改的业务问题、主题或成果范围；`nodes` 保存分工和依赖。PPT 用 `outline_level: sections` 表达主题，主题数与页数独立；`pages` 表达用户已审阅的逐页方案，页数检查与条目对应。旧方案缺省按逐页处理。

每个内容项保留真实来源、待回答问题和具体完成条件。`points` 写重点与约束，`visual` 简述交付组织方式；尚未执行的分析保留为问题。检查计划应能辨别漏项、证据不足或约束不满足，无需在规划时跑完整验证。

## 交付前只问三个问题

- 用户能否改范围、重点、成果或约束？
- 专业技能是否拿到了足够的输入与验收条件，并保有内部组织工作的空间？
- 去掉任务名称后内容是否依然完全通用？若是，补充材料中的具体对象、线索和约束。

方案到达可审阅程度即交付，细化工作随执行推进。
