# 元景保存：部署、故障恢复与集成验收

日常任务使用[保存入口](yuanjing.md)。本页用于服务异常、部署变化或集成验收。

HTML 是 plan.json 的阅读器和编辑器。主流程为：读取材料并形成具体方案 → 启动保存服务 → 交付 plan.html 与 plan.json，在侧栏审阅 HTML → 用户编辑并点击顶部“保存修改” → 用户在对话说“按方案执行” → 重新读取磁盘 plan.json。

## 启动与交付

日常任务运行下列命令，ready 后交付。状态报错时针对错误修复一次；仍失败则交付已有方案，说明保存连接未完成并保留现场。

将本次任务唯一的 plan.json 放在宿主可交付目录中的独立任务文件夹内，HTML 与服务状态文件放同目录。prepare_plan.py 已完成校验，通过 Bash 工具的 run_in_background 启动：

```sh
python <skill>/scripts/plan_server.py --plan <绝对任务目录>/plan.json --html <绝对任务目录>/plan.html --meta <绝对任务目录>/.plan-server.json
```

服务使用 Python 标准库，仅监听回环随机端口，启动时渲染随包 HTML 并注入真实存储连接。启动验收以状态文件和健康检查为准；部分宿主在后台任务结束后才返回输出，因此持续服务可能暂时没有可见的 stdout。TaskOutput 的 `block=true` 用于等待任务结束，服务启动后无需等待它完成，也不要因没有输出再次启动同一服务。需要查看任务状态时用 `block=false`。

另发一次 Bash 检查：

```sh
python <skill>/scripts/service_status.py <绝对任务目录>/.plan-server.json
```

命令认证读取服务中的方案并与磁盘核对，返回 ready、revision、plan、html、delivery_files 和 execution_plan。状态文件未出现时查看后台任务具体报错。服务适用 macOS/Linux（元景 Linux 沙箱）；同一 plan.json 的跨进程锁会阻止重复启动。锁文件保留在任务目录，进程退出时自动释放，无需删除。

服务 ready 仅表示保存通路就绪；方案执行条件以编译输出或 `plan_status.py plan.json` 为准。

状态检查得到 `ready: true` 后，用 PresentToUser 同时交付 delivery_files 中的 plan.html 和 plan.json；按宿主实际工具参数传入两个文件路径，核对成功回执包含两个文件。缺一个就补交该文件，然后再宣布方案已交付。检查文件尚未出现时先查看后台任务状态或具体错误，不展示完整状态文件，也不反复阻塞等待。健康检查只证明沙箱内服务运行；浏览器连接须由侧栏实际加载与保存验证。不要再用普通 render 覆盖已连接的 HTML；不要把 plan.json 另复制成执行入口，否则页面保存与执行可能引用不同文件。交付的 JSON 是审阅快照；后续执行始终读取 execution_plan 指向的原文件最新版本，用户无需重新上传。服务状态文件含临时写入凭据，保留在任务目录中，勿展示其内容。

默认允许页面来源 `http://127.0.0.1:17860`。宿主前端来源确实不同则用 `--origin <实际来源>` 指定。服务端限定当前计划、校验版本与哈希，校验成功后原子写入并读回，随后刷新 HTML。保存只更新计划，不执行任务。旧页面请求返回版本冲突，不覆盖新方案；页面保留草稿供合并。

本地沙箱通过元景的端口转发向 HTML 提供保存连接。实际环境需验证 localhost 是否可达：出现 `/sessions/...` 路径不能单独判断是云端。若使用云端沙箱，查阅宿主明确提供的端口访问能力；没有可用通路时报告该部署中的连接失败，保留草稿，禁止宣称保存成功或临时上传到外部服务。无需修改元景客户端源码。

## 保存与最新版本

顶部“保存修改”提交需求、模块和具体内容大纲的修改。模块弹窗“完成编辑”仅修改草稿。收到服务返回 persisted=true、plan、hash 后显示“已保存 vN”；断连、校验失败和冲突都显示失败并保留草稿。

页面打开时从服务重新加载最新 plan.json。服务跨轮保持运行，同一计划只启动一个实例；失联时用原计划重启服务并重新交付连接后的 HTML。重复启动会返回“已有保存服务”；复用现有连接，升级脚本时先停止旧进程再启动。沙箱关闭后服务结束，不承诺永久在线。

用户说“按方案执行”时，无论其是否提到修改，都重新读取固定任务目录的 plan.json，核对受影响的内容、页数、依赖与验收标准。保存后使用 reconcile 识别变化模块及下游，保留不受影响的记录；仅因编辑产生的必要语义修正由 Agent 处理，改变用户取舍时再说明并确认。

## 部署验收（环境首次接入或变更时）

发布或部署环境变化时完成：HTML 编辑 → 保存成功 → 下一轮读取 plan.json 确认修改与版本 → 再打开 HTML 读回同一修改。保留修改前后版本证据。HTTP 单元测试通过只证明保存服务，不能替代元景侧栏与端口转发的集成测试。自动打开侧栏须由宿主真实支持并观察到打开，不能凭交付成功推断。

删除模块表示取消该模块及其独占交付。保存服务同步移除专属交付物、无剩余负责人使用的能力需求与独占需求，保留共用内容，记录 scope_changes。仍有下游依赖时先调整其输入与依赖或一并删除；保存前可恢复。用户确认执行时复核剩余目标和说明中是否仍提及已取消成果，再按最新范围执行。范围记录保留在方案中，删除不启动执行。

“导出备份”保留未保存内容和删除标记，仅用于故障恢复；正常流程仍在页面保存。备份绑定原始方案版本，版本冲突时需合并，导入不会自动执行。
